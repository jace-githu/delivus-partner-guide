# 계약부터 첫 출고까지

신규 화주사가 계약 후 정식 운영까지 밟는 절차입니다.

## 전체 절차 한눈에 보기

1. **사전 협의** — 운영 조건 확인 (사전 질문지)
2. **연동 준비** — API 발급, 알림톡 설정, 송장 확인
3. **테스트** — API 연동 · 실주문 · 반품 테스트
4. **정식 오픈**

## 1단계 — 사전 협의

계약 확정 후, 원활한 운영 세팅을 위해 아래 항목을 사전 질문지로 확인합니다.

- **담당자 지정** — 시스템 · 운영(CS) · 물류 담당자와 연락처
- **운영 조건** — 운영 요일, 예상 출고량, 주요 취급 상품의 사이즈·중량 범위
- **픽업** — 픽업 필요 여부, 픽업 주소와 현장 담당자, 희망 시간대
- **주문 커트라인** — 당일 출고 기준 주문 접수 마감 시각
- **반품 이용 여부**
- **고객 알림톡 설정** — 배송 전 안내 / 배송 완료 / 배송 미완료 / 수거 / 반품 알림 사용 여부
- **CS 소통 채널** — 선호하는 소통 채널과 방식

## 2단계 — 연동 준비

- API 연동을 위한 키 발급 요청
- 알림톡 발송 리스트 전달
- 송장 프린터기 필요 여부 및 송장 스티커(바코드 양식·식별코드) 확인
- 운송장 채번 방식 확인

자세한 내용은 [시스템 연동 안내](/start/integration)를 참고하세요.

## 3단계 — 테스트

정식 오픈 전, 주문 데이터가 정상적으로 전송되고 실제 배송까지 이어지는지 아래 순서로 검증합니다. 테스트 일정은 담당 채널에서 사전에 협의합니다.

| 순서 | 테스트 | 확인 내용 |
|---|---|---|
| 1 | **API 연동 및 주문 테스트** | 주문 데이터 전송, 운송장 채번, 배송 상태 수신이 정상 동작하는지 확인합니다. |
| 2 | **실주문 테스트 (10건 미만)** | 실제 배송까지 진행하는 소량 검증입니다. 진행 전 담당 채널로 사전 공유가 **필수**입니다. |
| 3 | **반품 테스트** | 반품 접수부터 회수까지의 흐름을 확인합니다. **반품 계약 화주사만 해당**됩니다. |

::: warning 실주문 테스트는 진행 전 반드시 공유해 주세요
실주문 테스트 건은 일반 배송 물량과 함께 처리됩니다. 사전 공유가 없으면 테스트 건이 구분되지 않아, 배송 이슈가 생겼을 때 확인과 대응이 늦어집니다. **테스트 일자 · 건수 · 송장번호**를 담당 채널로 미리 공유해 주세요.
:::

## 4단계 — 정식 오픈

테스트 검증이 완료되면 협의된 오픈 일자에 정식 운영을 시작합니다.

::: tip 첫 출고 전 꼭 확인하세요 — 수취인 출입정보
공동현관 출입정보 미기재·오입력은 당일 미배송의 가장 큰 원인입니다. 주문 접수 단계에서 **공동현관 비밀번호 등 출입정보를 필수 입력**으로 설정하시면 미배송을 크게 예방할 수 있습니다.
:::
